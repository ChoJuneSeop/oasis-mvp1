# OASIS 중립 검증 프로토콜 v1.0

이 문서는 OASIS 검증 전체(P1~P8, 쌍대, 고차, 통합)에 공통 적용한다.

## 규칙 0 — 확증편향 방지
검증의 목적은 OASIS를 통과시키는 것이 아니라, 명제가 틀렸을 때 실제로 실패하게 만드는 것이다.

## 사전등록
- 주요 가설, 반증조건, 비교군, 주평가지표, 판정기준, seed를 결과 확인 전에 커밋한다.
- 결과를 본 뒤 기준을 바꾸면 별도 post-hoc 분석으로 표시하고 원 사전등록 판정은 유지한다.

## 대조군 대칭성
- OASIS에 유리한 조건만 사용하지 않는다.
- 반드시 OASIS의 추가 구조가 불필요한 음성대조군(null/current-only, Markov/no-history 등)을 포함한다.
- 음성대조군에서 OASIS가 일관되게 큰 이득을 보이면 구조적 과민반응 또는 누출 가능성으로 본다.

## baseline 공정성
- baseline에도 동일한 train/test split, 정보 접근 범위, 평가 지표를 사용한다.
- OASIS에만 추가 정보 또는 유리한 튜닝을 허용하지 않는다.
- 가능한 경우 단순 baseline뿐 아니라 일반적인 상호작용 모델도 포함해 OASIS 고유성 주장을 분리한다.

## 데이터 누출 금지
- test label과 test-derived 통계를 학습에 사용하지 않는다.
- 전처리 통계는 train에서만 산출한다.
- seed와 split은 고정하고 모든 run을 보존한다.

## 보고 원칙
- PASS뿐 아니라 FAIL, PARTIAL, INCONCLUSIVE를 동일하게 기록한다.
- 평균만 보고하지 않고 반복별 분포, 효과크기, 실패율을 저장한다.
- 불리한 run을 삭제하지 않는다.

## 증거 등급
1. 구조/명세 검증: 정의한 구조가 내부적으로 작동하는지 확인. 현실 타당성 증거가 아님.
2. 합성 독립 반증검증: OASIS 공식과 다른 데이터생성 과정에서 구조 필요성을 시험. 현실 타당성 증거가 아님.
3. 외부/실증 검증: OASIS가 생성하지 않은 실제 또는 독립 공개 데이터에서 검증.
4. 재현/반복 검증: 독립 seed, 환경, 구현에서 재현성 확인.

합성실험의 성공만으로 'OASIS가 현실에서 검증되었다'고 표현하지 않는다.

## 고유성 판단
OASIS가 단순 baseline을 이겨도 일반적인 history×participation 상호작용 모델과 차이가 없으면, 해당 결과는 구조 필요성은 지지할 수 있으나 OASIS 고유성의 증거로 해석하지 않는다.
