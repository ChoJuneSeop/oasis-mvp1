# OASIS 수학모델 → 코드 역추적 감사 v0.1

기준 수학문서: `OASIS_이론수학_통합초안_v0.1_2026-09-05.docx`
감사 대상: 기존 `main` MVP + `oasis-core-v0.2`
목적: 수학에 이미 정의된 내용을 코드가 위반한 경우와, 수학 자체가 아직 계산법을 정의하지 않은 경우를 분리한다.

## 판정 등급

- **구현 불일치**: 수학모델에 명시된 구조가 코드에서 소실·변형됨.
- **부분 구현**: 방향은 맞지만 수학적 의미 전체를 구현하지 못함.
- **수학-알고리즘 미정의**: 수학모델이 추상 연산자로만 두어 canonical code를 정할 수 없음.
- **구현 가설**: 수학에서 직접 유도되지 않았지만 시험을 위해 추가한 알고리즘 가정.
- **일치**: 현재 코드가 수학모델의 명시 조건을 직접 만족.

## 핵심 추적표

## 기존 main에서 명백한 구현 불일치

1. 관계과정 방향을 저장한 뒤 `pairKey(a,b)`에서 정렬하여 `A↔B`로 축약한다. 관계과정 이력의 방향 정보가 실제 선택 단계에서 소실된다.
2. 재활성화에 `최근 18개`, `최대 80개`, `1200틱`, `위험도 차이 <=0.18`을 사용한다. 이 숫자들은 수학모델에서 유도되지 않았다.
3. `P_t(c)=exp(Ψ_t(c))/Z_t`가 구현되지 않고 후보 vote/rank가 직접 선택에 쓰인다.
4. `C_t`의 새 조합 발생을 측정하기보다 사전 정의된 gate/hidden story가 후보공간을 연다.
5. `λ_t`, 명시적 유보 `Σy=0`, 책임축 `ρ_t/Ĉ_t`, `d_F`가 없다.

## v0.2의 정확한 위치

`oasis-core-v0.2`는 수학모델의 canonical implementation이 아니다.

다음은 수학에서 직접 확정된 사실에 가깝다.
- 관계과정 이력 `h_t`가 현재 판단에 참여해야 한다.
- 현재 흐름 `f_t`가 재활성 상태 `a_t`와 관계잠재에 영향을 줘야 한다.
- 과거 경험의 중요도는 영구 고정값이 아니다.

그러나 v0.2의 아래 규칙은 **구현 가설**이다.

`past.end == flow.start AND shared relational counterpart`

수학 원본에는 이 논리식이 없다. 따라서 v0.2의 12/12 test는 이 구현 가설의 내부 일관성 시험이지 OASIS 수학모델의 완전한 번역 증명이 아니다.

## 수학적 미정의 항목 — 코딩 전에 해결 필요

1. `f_t`: 현재 현실 흐름을 계산가능하게 표현하는 최소 구조.
2. `h_t`: 관계과정 이력을 어떤 수학 객체로 보존하는지.
3. `a_t`: 과거 완결경험의 현재 재활성 상태를 결정하는 연산자.
4. `κ_t(U)`: 흐름·이력·참여·재활성의 관계 상호작용 계산.
5. `G_t`: 여러 `κ_t(U)`를 비선형으로 결합해 `Ψ_t(c)`를 만드는 규칙.
6. `C_t` 생성 연산자: 독립 행동목록이 아닌 가능성 조합을 어떻게 생성하는지.
7. `D_t`: 확률 최대화와 동일하지 않은 단일 현실화/유보 연산자.
8. `W_t`: 현실화·미현실화 가능성을 포함한 전체 관계 재작성 연산자.
9. `Cl(C_t)`: 구조적 확장을 판별하기 위한 국소 닫힘.
10. `H_resp`, `A_search`, `A_t`: 동적 책임축과 계산자원 제어.
11. `d_F`: 나선적 비동일성을 측정하는 인연필드 거리.

## 감사 결론

현재 문제는 둘 다 존재한다.

**A. 실제 번역 오류/누락**
- 방향 소실
- 확률분포 미구현
- 사전 gate 기반 구조확장
- λ/유보/책임축 미구현
- 임의 고정 임계값·창

**B. 수학 → 알고리즘 공백**
- 재활성 연산자
- κ/G
- C_t 생성
- D_t
- W_t 전체 재작성
- 책임축 세부규칙
- d_F

따라서 다음 단계는 기존 코드를 계속 패치하는 것이 아니라, 위 11개 중 OASIS의 핵심 결합을 형성하는 `f_t, h_t, a_t, C_t, W_t`를 먼저 계산가능한 수학/알고리즘 명세로 고정한 뒤 코드를 다시 번역하는 것이다.
