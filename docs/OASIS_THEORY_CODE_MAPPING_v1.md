# OASIS 논문검증 기준 구현본 v1 — 이론·알고리즘·코드 대응표

## 상태

이 문서는 실험 결과가 아니라 구현 기준 문서다. `implementation/oasis-integrated-core-v1` 브랜치의 권위 진입점은 `src/oasis-reference-core.mjs`다.

계층은 다음과 같다.

- `src/oasis-core.mjs`: 현실 흐름·인연필드 재구성·완결 경험·현실 재작성·나선 계보·단일 실제화 기반
- `src/oasis-integrated-core.mjs`: 현재/과거 행동 가능성 통합·구조적 가능성 조합·책임 비지배 전선·현재 흐름 앵커링 기반
- `src/oasis-reference-core.mjs`: 책임 지속성, 책임 보유와 책임 해결 분리, 현재 비관계 변화 앵커링, 중복 역사행동 조합 차단, 동률 후보의 비고정 현실화 보정

OASIS는 한 시점의 고정 상태를 점수화해 최적 행동을 고르는 모델로 구현하지 않는다.

기본 연산 흐름은 다음과 같다.

`현실 흐름 관측 -> 현재 변화에서 관계과정 재구성 -> 참여상태 구성 -> 현재와 연결된 완결 경험 재참여 -> 가능성 구조 생성/재조합 -> 책임 검토 -> 단일 현실화 -> 실제 결과 -> 다음 현실 재작성 -> 이후 현재에서 과거 경험 재활성화`

이 중 일부만 구현한 코드는 OASIS 최종 구현으로 부르지 않는다.

## 1. 흐름

코드: `observe()`

- 현실은 이벤트 스트림으로 누적된다.
- 새 사건은 기존 현재를 덮어쓰는 단일 좌표가 아니라 이전 현실을 변화시키는 사건으로 기록된다.
- 각 사건은 `before`, `after`, `changedEntities`, `previousChoiceId`를 가진다.
- `danger` 같은 단일 현실 스칼라는 OASIS 코어에 존재하지 않는다.
- 이질성은 정상/비정상 값으로 미리 분류하지 않는다. 이후 관계와 행동의 전개로 관찰한다.

## 2. 관계과정 / 인연필드

코드: `reconstituteAffinityField()`

- 인연필드는 영구 점수나 활성 객체가 아니다.
- 현재 변화에 참여한 존재와 현재 참여자를 출발점으로 실제 완결 경험을 시간 역방향으로 추적한다.
- 관계의 방향과 과거 순서를 보존한다.
- 고정 유효기간, 최근 N개 경험, 유사도 임계값을 사용하지 않는다.
- 완결 경험에는 그 시점에 실제화된 관계과정만 저장하며 과거 인연필드 전체를 복제하지 않는다.
- 과거 재활성 경험은 ID 계보로 연결하여 전체기억 재귀호출을 막는다.

## 3. 참여상태

코드: `deriveParticipation()`

- 현재 행동 가능한 참여자와 과거 경험 속 역사적 참여자를 분리한다.
- 참여자는 고정 위험등급에 의해 ON/OFF 되지 않는다.
- 현재 영향을 받는 존재와 책임을 가진/수행 가능한 참여자를 함께 기록한다.
- 전사·치유사·주시자 같은 구체 역할은 어댑터가 제공할 수 있으나 코어는 특정 역할명을 고정하지 않는다.

## 4. 가능성 조합

코드: `generatePossibilities()` + `OASISReferenceCore._reactivatedAffordances()`

가능성은 세 층으로 형성된다.

1. 현재 현실이 허용하는 직접 행동
2. 현재와 다시 관계 맺은 완결 경험에서 현재도 수행 가능한 행동의 재참여
3. 현재/재활성 행동들이 전제조건·관계·책임 해결을 통해 연결되면서 새로 만들어지는 구조적 조합

제약:

- 가능성 개수 상한, top-k, 고정 점수화를 두지 않는다.
- 과거 행동은 현재 능력과 현재 관계 참여가 없으면 재생되지 않는다.
- 현재 행동과 재활성 행동이 사실상 같은 원행동이면 이를 두 단계 행동처럼 중복 결합하지 않는다.
- 책임을 해결하는 후속 행동은 가능성 공간 자체를 확장할 수 있다.

## 5. 책임축

코드: `OASISReferenceCore._responsibilityFor()`

- 책임은 숫자 가중치가 아니다.
- 각 가능성이 만드는 책임뿐 아니라, 그 가능성에 실제로 참여하는 현재 존재가 이미 지고 있는 책임도 현재 판단에 남는다.
- `책임 담당자가 있음`, `수행 능력이 있음`, `실제로 책임을 해결함`을 서로 다른 상태로 기록한다.
- 실제 `resolves` 관계가 포함된 행동만 해당 책임을 해결한 것으로 처리한다.
- 생명과 같은 대전제는 효용과 교환되는 위험점수가 아니라 명시적 invariant(불변 제약)으로 처리한다.

영문 설명:
- `Invariant`는 다른 선호나 점수와 교환하지 않는 명시적 불변 제약이다.

## 6. 선택축

코드: `OASISReferenceCore.choose()`

선택은 총점 합산이나 argmax로 결정하지 않는다.

1. 명시적 불변 제약 충돌 후보를 제외한다.
2. 남은 후보끼리 미해결 책임의 집합 포함관계를 비교해 책임 비지배 전선을 만든다.
3. 그 전선에서 이번 현재 사건의 실제 변화와 직접 관계되는 후보가 있으면 현재 흐름 후보군을 형성한다.
4. 의미축으로 후보가 하나만 남으면 그대로 단일 선택한다.
5. 의미적으로 동등한 후보가 여러 개 남으면 고정 사전순서가 아니라 `realizationSeed + 현재까지의 전체 흐름 fingerprint + 후보 구조`로 하나의 현실화를 발생시킨다.

5번은 선호나 성능점수가 아니다. 현실은 하나로 실제화되어야 하지만 현재 의미구조가 어느 하나를 우월하다고 말하지 못하는 경우의 **비선호적 현실화 장치**다.

같은 seed와 같은 흐름은 재현되며, 다른 seed에서는 동등 전선의 다른 가능성이 현실화될 수 있다. `tieBreakUsed=true`인 사례는 의미적으로 하나가 결정된 사례와 분리해 분석한다.

영문 설명:
- `realization seed`는 의미적으로 동등한 가능성 중 하나의 실제화를 재현 가능하게 기록하는 난수 초기값이다.
- `fingerprint`는 전체 흐름을 구조적으로 식별하는 재현 가능한 표현이다.

## 7. 단일 현실화

코드: `actualize()`

- 한 deliberation(판단과정)에서 하나의 선택만 실제화한다.
- 선택되지 않은 가능성은 완결 경험으로 저장하지 않는다.
- 다른 선택 ID를 강제로 결과화하려 하면 오류를 낸다.

영문 설명:
- `Deliberation`은 현재 현실에서 관계, 참여, 가능성, 책임을 함께 검토해 하나의 선택에 이르는 판단과정이다.

## 8. 결과 -> 다음 현실 재작성

코드: `actualize()` -> `observe(outcome)`

- 선택의 결과는 reward가 아니다.
- 결과 사건이 실제 세계의 사실·관계·참여·행동가능성을 바꾼다.
- 그 결과가 다음 판단의 현재 조건이 된다.
- 미실현 가능성은 영구 가중치로 남지 않고 다음 현재에서 다시 생성된다.

## 9. 완결 경험

실제 선택과 실제 결과가 모두 존재할 때만 `closedExperiences`에 기록한다.

관찰만 한 사건, 선택되지 않은 후보, 미래 추정, 단순 가능성은 완결 경험이 아니다.

## 10. 나선

코드: `spiralLineage`

나선은 숫자 보상 카운터가 아니다.

`과거 완결 경험 -> 현재 재참여 -> 선택 -> 실제 결과 -> 새 완결 경험`

의 계보 자체를 기록한다.

## 11. 구조적 확장

코드: `structuralExpansion`

새 경험이나 현실 변화 뒤 이전에 없던 관계장·참여·가능성 조합·선택구조가 나타났는지를 구조 서명으로 기록한다. 새 구조가 많다고 더 좋다고 판정하지 않는다.

## 12. 기본조건 최소개입

코어는 행동 가능성이 없다고 스스로 기본조건을 주입하지 않는다.

`continuationRequired = true`

를 반환하고, 실험 전체가 이 때문에 지속 불가능한 경우에만 외부 하네스가 최소 공통 조건을 추가한다. 개입은 별도 사건으로 기록한다.

## 13. 기존 코드에서 폐기한 알고리즘

논문검증 권위 코어에서는 다음을 사용하지 않는다.

- `danger >= x`
- 위험 유사도 `±x`
- 관계 유효기간 `N tick`
- fixed score / fixed weight
- top-k 가능성 제한
- argmax
- 관계 방향을 지우는 정렬 pair key
- `possibilities[0]`을 의미 있는 선택으로 사용하는 방식
- 고정 구조키의 사전식 첫 항목을 의미적 선택으로 사용하는 방식
- 안정화/복귀/churn을 OASIS 성공목표로 사용하는 방식

## 14. 구현 감사 필수 항목

실험 전 구현축은 최소 다음을 확인한다.

- 현실 이벤트가 누적되는가
- 관계 방향·순서가 보존되는가
- 오래된 경험이 시간만으로 삭제되지 않는가
- 현재와 무관한 경험이 자동 활성화되지 않는가
- 과거 인연필드 전체가 새 경험 안에 재귀 복사되지 않는가
- 참여상태가 고정 위험값으로 결정되지 않는가
- 가능성 구조가 고정 후보목록으로 닫혀 있지 않는가
- 현재 수행능력이 없는 과거 행동이 재생되지 않는가
- 같은 원행동이 현재/과거 복제본으로 중복 조합되지 않는가
- 현재 참여자의 기존 책임이 후보가 명시하지 않았다는 이유로 사라지지 않는가
- 책임 보유와 실제 책임 해결이 분리되는가
- 책임축이 가능성 생성과 선택 모두에 영향을 주는가
- 관계선이 없어도 이번 현재에서 실제로 변한 존재가 판단에 참여하는가
- 한 시점 한 선택만 실제화되는가
- 실제 선택/결과만 완결 경험이 되는가
- 결과가 다음 현실을 실제 변경하는가
- 과거 경험과 새 경험 사이 나선 계보가 남는가
- 기본조건이 코어 내부에서 자동 주입되지 않는가
- 의미적 동률 선택이 고정 사전순서로 위장되지 않는가
- 동률 현실화에 사용한 seed가 기록되는가

## 15. 아직 열린 구현 경계

다음은 코딩되어 있으나 OASIS의 철학적 정답으로 확정하지 않는다.

- 의미적으로 동등한 비지배 후보의 contingent realization(우열 없는 단일 현실화) 방식
- 외부 세계가 제공하는 원자 행동 affordance 표현
- 물리세계/역사세계/게임세계 사이의 행동결과 어댑터

이 항목은 OASIS 우월성 근거가 아니라 이후 제거실험과 강한 비교군으로 계속 공격해야 할 구현 경계다.

영문 설명:
- `Affordance`는 현재 환경에서 실제로 실행 가능한 행동 기회 또는 행동 가능성이다.
- `Contingent realization`은 의미구조가 어느 하나를 우월하다고 결정하지 못하는 경우 동등한 가능성 중 하나가 실제 현실로 발생하는 과정을 뜻한다.
