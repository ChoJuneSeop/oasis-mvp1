# OASIS 논문검증 기준 구현본 v1 — 이론·알고리즘·코드 대응표

## 상태

이 문서는 실험 결과 문서가 아니라 구현 기준 문서다. `implementation/oasis-integrated-core-v1` 브랜치의 `src/oasis-core.mjs`를 논문검증용 OASIS 통합 기준 구현본으로 감사하기 위한 기준을 고정한다.

## 핵심 원칙

OASIS는 한 시점의 고정 상태를 점수화해 최적 행동을 고르는 모델로 구현하지 않는다.

기본 연산 흐름은 다음과 같다.

`현실 흐름 관측 -> 현재 변화에서 관계과정 재구성 -> 참여상태 구성 -> 가능성 구조 생성/재조합 -> 책임 검토 -> 단일 선택 -> 실제 결과 -> 다음 현실 재작성 -> 이후 현재에서 과거 경험 재활성화`

이 중 일부만 구현한 코드는 OASIS 최종 구현으로 부르지 않는다.

## 1. 흐름

코드: `observe()`

- 현실은 이벤트 스트림으로 누적된다.
- 새 사건은 기존 현재를 덮어쓰는 단일 좌표가 아니라 이전 현실을 변화시키는 사건으로 기록된다.
- 각 사건은 `before`, `after`, `changedEntities`, `previousChoiceId`를 가진다.
- `danger` 같은 단일 현실 스칼라는 OASIS 코어에 존재하지 않는다.
- 이질성은 별도 정상/비정상 값으로 분류하지 않는다. 새 사건은 이후 흐름에서 어떤 관계를 형성하는지로 관찰한다.

## 2. 관계과정 / 인연필드

코드: `reconstituteAffinityField()`

- 인연필드는 영구 저장 점수나 활성 객체가 아니다.
- 현재 변화에 참여한 존재와 현재 참여자를 출발점으로, 실제로 완결된 과거 경험을 시간 역방향으로 추적한다.
- 관계의 방향과 과거 순서를 보존한다.
- 고정 유효기간, 최근 N개 경험, 유사도 임계값을 사용하지 않는다.
- 재활성화된 경험에는 그 경험에서 실제로 새로 형성·실현된 관계과정만 포함한다.
- 과거 인연필드 전체를 새 경험 안에 복사하지 않고, 재활성된 과거 경험은 ID 참조로 연결한다. 이로써 전체 기억이 재귀적으로 뭉쳐 따라오는 오염을 막는다.
- 현재에서 의미를 얻지 못한 경험은 단순히 오래됐다는 이유가 아니라 현재 관계과정과 연결되지 않기 때문에 참여하지 않는다.

## 3. 참여상태

코드: `deriveParticipation()`

- 현재 행동 가능한 참여자와 과거 경험 속 역사적 참여자를 분리한다.
- 참여자는 고정 위험등급에 의해 ON/OFF 되지 않는다.
- 현재 관계장에 영향을 받는 존재와 책임을 수행할 수 있는 현재 참여자를 함께 기록한다.
- 전사/치유사/주시자 같은 역할은 세계 어댑터가 역할/능력으로 제공할 수 있으나, 코어는 특정 역할명을 고정하지 않는다.

## 4. 가능성 조합

코드: `generatePossibilities()`

가능성은 두 층으로 형성된다.

1. 현재 현실이 실제로 허용하는 직접 행동 가능성
2. 현재 행동들이 관계·전제조건·결과책임을 통해 서로 연결되면서 새로 만들어지는 구조적 조합

특징:

- 가능성 개수 상한을 두지 않는다.
- top-k를 사용하지 않는다.
- 가능성을 미리 점수화하지 않는다.
- 현재 유한한 행동 가능성 집합에서 구조적 폐쇄가 끝날 때까지 조합을 생성한다.
- `requires/provides` 관계뿐 아니라 어떤 행동이 만든 책임을 다른 행동이 해결할 수 있을 때도 새로운 조합을 생성한다.
- 따라서 책임축은 선택 후 벌점이 아니라 가능성 공간 자체를 다시 구성할 수 있다.

## 5. 책임축

코드: `_responsibilityFor()`

- 책임은 숫자 가중치가 아니다.
- 각 가능성이 만드는 의무, 해결된 의무, 미해결 의무, 영향을 받는 존재를 집합으로 추적한다.
- 현재 참여자가 가진 의무/능력이 실제로 책임을 감당할 수 있는지 연결한다.
- 생명과 같은 대전제는 숫자 위험 임계값이 아니라 명시적 invariant(불변 제약)으로만 처리한다.

영문 설명:
- `Invariant`는 다른 선호나 점수와 교환하지 않는 명시적 불변 제약을 뜻한다.

## 6. 선택축

코드: `choose()`

선택은 점수 합산이나 argmax로 결정하지 않는다.

1. 명시적 불변 제약을 위반하는 가능성은 선택가능 집합에서 제외한다.
2. 남은 가능성끼리 다음 관계를 집합 포함관계로 비교한다.
   - 미해결 책임
   - 현재 관계의 지지
   - 재활성화된 경험의 지지
   - 실제 참여자 포함
3. 한 가능성이 다른 가능성보다 모든 면에서 열등하지 않고 일부 면에서 더 구조적으로 포괄적일 때만 지배관계를 인정한다.
4. 지배되지 않은 가능성들만 현재 선택전선에 남긴다.
5. 여러 가능성이 끝까지 비동등하게 남으면 계산 재현성을 위한 결정적 구조키로 하나를 현실화한다.

영문 설명:
- `Pareto frontier`는 하나의 총점으로 줄이지 않고 서로 다른 기준에서 어느 하나가 완전히 지배하지 못하는 후보들의 집합이다.

### 중요한 제한

마지막 결정적 구조키는 OASIS 철학적 선호가 아니다. 계산상 단일 현실화를 보장하는 타이브레이커다.

따라서 `tieBreakUsed=true`인 사례는 논문에서 선택 우월성 근거로 사용해서는 안 된다.

## 7. 단일 현실화

코드: `actualize()`

- 한 deliberation(판단과정)에서 하나의 선택만 실제화할 수 있다.
- 선택되지 않은 가능성은 실제 경험으로 저장되지 않는다.
- 다른 선택 ID를 강제로 결과화하려 하면 오류를 낸다.

영문 설명:
- `Deliberation`은 현재 현실에서 관계, 참여, 가능성, 책임을 함께 검토해 하나의 선택에 이르는 판단과정을 뜻한다.

## 8. 결과 -> 다음 현실 재작성

코드: `actualize()` -> `observe(outcome)`

- 선택의 결과는 단순 reward가 아니다.
- 결과 사건이 실제 세계의 사실·관계·참여·행동가능성을 바꾼다.
- 그 결과가 다음 `deliberate()`의 현재 조건이 된다.
- 미실현 가능성은 영구 가중치로 유지되지 않고 다음 현재에서 다시 생성된다.

## 9. 완결 경험

실제 선택과 실제 결과가 모두 존재할 때만 `closedExperiences`에 기록된다.

따라서:

- 관찰만 한 사건
- 선택되지 않은 후보
- 미래 추정
- 단순 가능성

은 완결 경험이 아니다.

## 10. 나선

코드: `spiralLineage`

나선은 숫자 보상 카운터가 아니다.

과거 완결 경험이 이후 현재에서 재활성화되고, 그 재활성화가 참여한 새로운 선택이 다시 실제 결과를 만들어 새 완결 경험이 될 때 경험 간 계보를 남긴다.

즉:

`과거 경험 -> 현재 재참여 -> 선택 -> 결과 -> 새 경험`

의 연결 자체가 나선의 구현 대상이다.

## 11. 구조적 확장

코드: `structuralExpansion`

새로운 경험이나 현실 변화 뒤에 이전에 없던

- 관계장 구조
- 참여 구조
- 가능성 조합
- 선택구조

가 나타났는지를 구조 서명으로 기록한다.

새 구조가 많다고 더 좋다고 판정하지 않는다.

## 12. 기본조건 최소개입

코어는 스스로 행동 가능성을 만들 수 없을 때 자동으로 기본조건을 주입하지 않는다.

대신:

`continuationRequired = true`

를 반환한다.

실험 하네스가 전체 실험을 지속할 수 없는 경우에만 공통 최소조건을 추가하고, 그 개입을 별도 사건으로 기록해야 한다.

## 13. 기존 코드에서 폐기한 알고리즘

논문검증 OASIS 코어에서는 다음을 사용하지 않는다.

- `danger >= x`
- 위험 유사도 `±x`
- 관계 유효기간 `N tick`
- 고정 score / fixed weight
- top-k 가능성 제한
- argmax
- 관계 방향을 제거하는 정렬 pair key
- `possibilities[0]`을 의미 있는 선택으로 취급
- 안정화/복귀/churn을 OASIS 성공목표로 사용

## 14. 구현 감사에서 반드시 확인할 사항

실험 전 4축 감사의 구현축은 최소 다음을 검사한다.

- 흐름 이벤트가 실제로 누적되는가
- 관계 방향이 보존되는가
- 관계 순서가 보존되는가
- 오래된 경험이 시간만으로 삭제되지 않는가
- 현재와 무관한 경험이 자동 활성화되지 않는가
- 과거 인연필드 전체가 새 경험 안에 재귀 복사되지 않는가
- 참여상태가 고정 위험값으로 결정되지 않는가
- 가능성 구조가 고정 후보목록으로 닫혀 있지 않는가
- 책임축이 가능성 생성과 선택 모두에 영향을 주는가
- 한 시점 한 선택만 실제화되는가
- 실제 선택/결과만 완결 경험이 되는가
- 선택 결과가 다음 현실을 실제 변경하는가
- 과거 경험 재참여와 새 경험 사이의 나선 계보가 남는가
- 기본조건이 코어 내부에서 자동 주입되지 않는가

## 15. 아직 이론적으로 열어 둔 부분

다음은 코딩되어 있지만 OASIS의 철학적 정답으로 확정하지 않는다.

- 비지배 후보가 여러 개 남았을 때의 계산상 타이브레이커
- 외부 세계가 제공하는 원자 행동(affordance)의 표현 방식
- 물리세계/역사세계/게임세계 사이의 행동결과 어댑터

이 항목들은 검증 결과를 보고 OASIS의 우월성을 주장하는 근거가 아니라, 별도 제거실험과 강한 비교군으로 계속 공격해야 할 구현 경계다.

영문 설명:
- `Affordance`는 현재 환경에서 실제로 실행 가능한 행동 기회 또는 행동 가능성을 뜻한다.
