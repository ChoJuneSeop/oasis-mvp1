# OASIS 논문검증 기준점 고정 — 2026-09-06

## 목적

이 문서는 OASIS 논문검증을 다시 시작할 때 기준 구현과 검증 조건이 이전 상태로 회귀하지 않도록 현재 합의·구현 상태를 고정한다.

## 권위 브랜치

`implementation/oasis-integrated-core-v1`

`main`은 이 기준점 작성 시점에 변경하지 않는다.

## 권위 구현

논문검증용 OASIS의 단일 외부 진입점은:

`src/oasis-reference-core.mjs`

계층 구조:

- `src/oasis-core.mjs`: 현실 흐름, 관계과정 재구성, 완결 경험, 실제 결과에 의한 세계 재작성, 나선 계보, 단일 현실화의 기반 계층
- `src/oasis-integrated-core.mjs`: 현재 행동 가능성과 과거 완결 경험의 재참여, 구조적 가능성 조합, 참여·책임·현재 흐름 중심의 선택 계층
- `src/oasis-reference-core.mjs`: 논문검증에서 실제 사용하는 최종 권위 계층. 책임 보유와 책임 해결을 분리하고, 관계선이 없어도 현재 변화가 의사결정에 참여하도록 현재 흐름 앵커링을 보강한다.

## 고정된 핵심 알고리즘 원칙

기본 연산 흐름:

`현실 흐름 관측 -> 현재 변화에서 관계과정 재구성 -> 현재와 연결되는 과거 완결 경험 재활성화 -> 참여상태 구성 -> 현재 행동 가능성과 과거 경험 행동의 재참여 -> 구조적 가능성 조합 -> 책임/불변제약 검토 -> 단일 현실화 -> 실제 결과 -> 다음 현실 재작성 -> 새 완결 경험 -> 이후 현재에서 재활성화 -> 나선 계보`

다음 원칙을 유지한다.

1. 현재는 고정 좌표가 아니라 연속 현실 흐름으로 처리한다.
2. 관계의 방향, 순서, 맥락을 보존한다.
3. 인연은 고정 객체·점수·영구 가중치가 아니라 현재 흐름과 관계되는 과거 완결 경험의 재참여로 구현한다.
4. 과거 인연필드 전체를 새 경험에 재귀 복사하지 않는다. 과거 경험은 ID 계보로 참조한다.
5. 참여상태는 고정 위험 임계값으로 ON/OFF하지 않는다.
6. 가능성은 고정 top-k/후보 점수표로 닫지 않는다.
7. 구조적 조합은 단순히 같은 존재를 포함한다는 이유로 생성하지 않는다. 전제조건 전달, 생성-요구 연결, 책임 해결 등 명시적 과정 연결고리가 있어야 한다.
8. 책임을 가진 참여자가 존재하거나 수행능력이 있다는 사실을 책임이 이미 해결됐다는 것으로 간주하지 않는다.
9. 현재 참여자가 이미 지고 있는 책임은 특정 후보 행동에 다시 명시되지 않았다는 이유로 사라지지 않는다.
10. 명시적 불변 제약은 다른 점수와 교환하지 않는다.
11. 의미적으로 동등한 비지배 후보가 여러 개 남을 경우 고정 사전식 우선순위를 OASIS 의미판단으로 사용하지 않는다. 단일 현실화가 필요하면 기록 가능한 realization seed를 사용하며, 이는 성능 또는 선호 근거로 해석하지 않는다.
12. 한 판단과정에서 하나의 선택만 현실화한다.
13. 실제 선택과 실제 결과가 모두 있을 때만 완결 경험으로 저장한다.
14. 선택 결과는 reward가 아니라 다음 현실의 사실·관계·참여·행동가능성 변경으로 반영한다.
15. 코어는 기본조건을 자동 주입하지 않는다. 실험이 지속 불가능할 때 외부 하네스만 최소 기본조건을 제공하고 그 개입을 별도 사건으로 기록한다.

## 사용 금지 — 과거 OASIS 구현의 회귀 경로

새 논문검증에서 다음을 OASIS 본체로 사용하지 않는다.

- `relation-field.js`의 1200 tick 관계 유효기간
- ±0.18 위험 유사도
- `danger >= 0.38` 참여 분기
- 방향을 없애는 pair 정렬
- RPG `danger` 스칼라 기반 순위/투표
- 고정 score / reward / weighted score
- argmax / top-k
- `possibilities[0]`을 의미 있는 선택으로 취급
- 안정화율, 복귀율, churn을 OASIS의 선험적 성공기준으로 사용
- 단순 공통 엔티티를 이유로 행동을 구조적 조합으로 결합

## 실험 선행 4축 감사

새 실험 전 반드시 아래 네 축을 통과해야 한다.

1. 성공값 감사 — 결과/성공/정상/복귀를 미리 정하지 않았는가
2. 평가기준 감사 — 기존 AI 성능지표가 OASIS의 의미판정으로 침투하지 않았는가
3. 흐름 감사 — 현재를 고정 상태나 단일 사건으로 절단하지 않았는가
4. 구현 감사 — 실제 실행 코드와 알고리즘이 최신 OASIS 원리를 왜곡·누락하지 않았는가

추가로 새 실험 전 킬서치를 수행하고, 강한 비교군과 반증조건을 포함한다.

## 기본조건 최소개입 원칙

실험을 지속할 수 없는 경우에만 최소한의 기본조건 제공을 허용한다.

- 목적은 실험 지속성 확보뿐이다.
- 정답·미래정보·위험판정·선호행동을 주입하지 않는다.
- 비교 시스템에 동일하게 적용한다.
- 자발적 진행구간 / 진행불능 / 기본조건 개입 / 이후 흐름을 분리 기록한다.
- OASIS가 자발적으로 진행 가능한 경우 불필요한 조건을 제공하지 않는다.

## CI / 구현감사 상태

최종 확인된 CI는 다음을 각각 검사하고 성공했다.

- 기반 코어 문법
- 통합 알고리즘 문법
- 권위 reference core 문법
- 기반 구현 감사
- 확장 통합 알고리즘 감사
- 권위 reference-core 감사
- PWA가 권위 reference core를 참조하는지 확인

중간 실패 이력은 삭제하지 않는다. 특히 `repair`와 `leave -> repair`가 불필요하게 같은 책임해결 후보로 남은 실패를 통해, 단순 공통 엔티티 연결이 구조적 관계과정이 아님을 확인했고 조합 알고리즘을 수정했다.

## 현재 상태의 의미

이 기준본은 OASIS 이론의 진실성이나 우월성을 증명한 결과가 아니다.

정확한 의미는:

**현재까지 확정한 OASIS의 흐름·관계과정·참여·가능성·선택·책임·현실재작성·완결경험·나선·구조확장을 논문 실험에서 최대한 왜곡 없이 실행하기 위한 기준 구현본이다.**

향후 실험에서 이 구현의 이론 왜곡 또는 알고리즘 오류가 발견되면 기존 결과와 새 결과를 분리하고, 구현 버전과 감사문서를 함께 갱신한다.

## 재개 규칙

다음 논문검증은 새 코드를 즉흥적으로 만들지 않고 반드시 `src/oasis-reference-core.mjs`를 출발점으로 한다.

실험 코드가 다른 OASIS 구현을 사용하려면 먼저 구현감사를 새로 통과해야 한다.
