# OASIS 논문검증 구현 기준본 v1

## 권위 구현

논문검증에서 OASIS를 실행할 때의 단일 진입점은 다음 파일이다.

`src/oasis-reference-core.mjs`

계층은 다음과 같다.

- `src/oasis-core.mjs`: 현실 흐름, 관계장 재구성, 완결 경험, 실제 결과에 의한 세계 재작성, 나선 계보, 단일 실제화의 기반 계층
- `src/oasis-integrated-core.mjs`: 과거 완결 경험의 현재 재참여, 실행가능성 조건, 가능성 조합, 책임 중심 비지배 선택전선, 현재 흐름 직접참여의 중간 계층
- `src/oasis-reference-core.mjs`: 현재 참여자가 이미 지고 있는 책임의 지속, 책임 보유와 책임 해결의 분리, 관계선이 없는 현재 변화의 앵커링, 동일 행동의 과거/현재 중복 조합 차단, 의미적으로 동등한 후보의 비고정 현실화를 보정한 최종 권위 계층

외부 실험 하네스와 실행 화면은 반드시 `src/oasis-reference-core.mjs`에서 `createOASIS`를 import한다.

## 새 논문검증에서 사용 금지

다음 파일/알고리즘은 과거 구현 기록 또는 비교용 자료일 뿐 최신 OASIS 논문검증 코어가 아니다.

- `relation-field.js`의 1200 tick 유효기간
- `relation-field.js`의 ±0.18 위험 유사도
- `relation-field.js`의 `danger >= 0.38` 참여 분기
- 방향을 제거하는 정렬 pair key
- 구 RPG의 `danger` 스칼라 기반 `evalOasis` 순위/투표 알고리즘
- `possibilities[0]`을 의미 있는 OASIS 선택으로 사용하는 방식
- 고정 score, reward, argmax, top-k를 OASIS의 판단 원리로 사용하는 방식
- 고정 구조키의 사전식 정렬로 의미적 동률을 항상 같은 후보로 보내는 방식
- 복귀율, 안정화율, churn 등을 OASIS의 선험적 성공기준으로 사용하는 방식

기존 파일은 과거 실험 재현과 비교군 검토를 위해 보존하되, 새 OASIS 주장 검증에 직접 사용하지 않는다.

## 현재 권위 알고리즘의 순서

`현실 사건 관측`
→ `현재 변화와 실제 참여자를 기준으로 관계장 재구성`
→ `현재와 연결된 완결 경험만 재활성화`
→ `현재 참여상태와 역사적 참여 분리`
→ `현재 행동 가능성 + 조건을 만족하는 과거 경험 행동의 재참여`
→ `동일 의미 행동의 과거/현재 중복 결합 차단`
→ `관계·전제조건·책임 해결에 의한 가능성 조합 확장`
→ `명시적 불변 제약 검사`
→ `현재 참여자가 이미 지닌 책임까지 포함해 미해결 책임 구성`
→ `책임 보유/수행능력과 실제 책임 해결을 분리`
→ `미해결 책임의 집합 포함관계로 비지배 후보 구성`
→ `현재 사건에서 실제로 변한 존재와 직접 관계된 후보 확인`
→ `의미적으로 동등한 후보가 남을 때 현재 전체 흐름 + 기록된 realization seed로 비선호적 단일 현실화`
→ `한 선택만 실제화`
→ `실제 결과가 세계의 사실·관계·참여·행동가능성을 변경`
→ `실제 선택+결과만 완결 경험으로 저장`
→ `이후 현재에서 관련 경험이 다시 의미를 얻으면 재참여`
→ `과거 경험과 새 완결 경험 사이에 나선 계보 기록`

## 동률 후보의 현실화 경계

책임과 현재 흐름이 후보를 하나로 결정하지 못했다고 해서 임의의 고정 사전순서가 OASIS의 철학적 선호가 되어서는 안 된다.

권위 코어는 이 경우 다음을 사용한다.

- 실행마다 기록되는 `realizationSeed`
- 그 시점까지의 전체 현실 흐름 fingerprint
- 후보의 구조적 정체성

이 세 요소로 의미적으로 동등한 선택전선에서 한 후보를 현실화한다. 이 값은 효용·성과·위험 점수가 아니며 후보의 우열을 뜻하지 않는다. 같은 seed와 같은 흐름은 재현되고, 다른 seed는 동등한 선택전선에서 다른 현실화를 허용한다.

이 장치는 OASIS의 독자적 우월성 근거가 아니다. `tieBreakUsed=true`인 실행은 **의미축으로 하나가 결정된 사례와 별도 표기**해야 한다.

영문 설명:
- `realization seed`는 의미적으로 동등한 가능성 중 하나의 실제 현실화를 재현 가능하게 기록하는 난수 초기값이다. 성능점수나 선호 가중치가 아니다.
- `fingerprint`는 그 시점까지의 현실 흐름 내용을 재현 가능하게 식별하는 구조적 표현을 뜻한다.

## 외부 세계와의 인터페이스 경계

코어는 현실을 스스로 만들어 넣지 않는다. 외부 환경 어댑터가 다음을 제공한다.

1. 현재 현실에서 실제로 관찰된 사실과 관계
2. 현재 현실에서 실제로 실행 가능한 원자 행동 기회
3. 실제화된 선택 뒤에 현실에서 발생한 결과

영문 설명:
- `Affordance`는 현재 환경이 실제로 허용하는 행동 기회 또는 실행 가능성을 뜻한다.
- `Adapter`는 역사자료, 게임세계, 물리환경 등 서로 다른 현실 표현을 OASIS 코어의 공통 입력형식으로 연결하는 변환 계층이다.

이 인터페이스는 실험별로 달라질 수 있지만 OASIS 코어의 내부 선택원리를 바꾸어서는 안 된다.

## 기본조건 최소개입

코어 자체는 진행 불능 시 기본조건을 자동 주입하지 않는다.

행동 가능성이 없으면 `continuationRequired=true`를 반환한다. 실험 전체가 이 상태 때문에 지속 불가능할 때에만 외부 하네스가 최소 공통 조건을 추가하고, 해당 입력을 `intervention` 사건으로 명시적으로 기록한다.

## 실험 전 구현 승인 조건

새 검증은 다음을 모두 만족해야 실행할 수 있다.

1. 실험 코드가 `src/oasis-reference-core.mjs`를 import한다.
2. OASIS 선행 4축 감사의 구현축을 통과한다.
3. `.github/workflows/oasis-integrated-core.yml`에서 기반 감사, 확장 알고리즘 감사, reference-core 감사가 모두 통과한다.
4. 실험 하네스가 새로운 고정 임계값, 점수, 위험값, 성공값을 OASIS 내부에 삽입하지 않는다.
5. 실험별 세계 어댑터가 제공하는 정보와 개입을 전부 기록한다.
6. `realizationSeed`가 사용된 동률 현실화와 의미축으로 단독 결정된 선택을 결과 분석에서 구분한다.

## 현재 의미

이 구현본은 OASIS 이론의 진실성을 증명하는 결과가 아니다. 현재까지 합의된 OASIS 개념을 실험 가능한 코드로 최대한 보존한 **논문검증 기준 구현본**이다.

향후 반증 실험에서 알고리즘 자체의 왜곡이나 누락이 발견되면 이 문서와 코드 버전을 함께 갱신하고, 기존 버전에서 얻은 결과와 새 버전의 결과를 구분한다.
