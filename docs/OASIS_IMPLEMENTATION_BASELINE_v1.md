# OASIS 논문검증 구현 기준본 v1

## 권위 구현

논문검증에서 OASIS를 실행할 때의 단일 진입점은 다음 파일이다.

`src/oasis-integrated-core.mjs`

이 파일은 `src/oasis-core.mjs`를 기반 계층으로 사용한다.

- `src/oasis-core.mjs`: 현실 흐름, 현재 관계장 재구성, 완결 경험, 실제 결과에 의한 세계 재작성, 나선 계보, 단일 실제화의 기반 계층
- `src/oasis-integrated-core.mjs`: 과거 완결 경험의 현재 재참여, 실행가능성 조건, 책임 중심 선택, 현재 흐름 직접참여를 반영하는 최종 의사결정 계층

따라서 두 파일이 함께 구현을 구성하지만 외부 실험 하네스는 반드시 `src/oasis-integrated-core.mjs`에서 `createOASIS`를 import한다.

## 새 논문검증에서 사용 금지

다음 파일/알고리즘은 과거 구현 기록 또는 비교용 자료일 뿐 최신 OASIS 논문검증 코어가 아니다.

- `relation-field.js`의 1200 tick 유효기간
- `relation-field.js`의 ±0.18 위험 유사도
- `relation-field.js`의 `danger >= 0.38` 참여 분기
- 방향을 제거하는 정렬 pair key
- 구 RPG의 `danger` 스칼라 기반 `evalOasis` 순위/투표 알고리즘
- `possibilities[0]`을 의미 있는 OASIS 선택으로 사용하는 방식
- 고정 score, reward, argmax, top-k를 OASIS의 판단 원리로 사용하는 방식
- 복귀율, 안정화율, churn 등을 OASIS의 선험적 성공기준으로 사용하는 방식

기존 파일은 과거 실험 재현과 비교군 검토를 위해 보존하되, 새 OASIS 주장 검증에 직접 사용하지 않는다.

## 현재 통합 알고리즘의 순서

`현실 사건 관측`
→ `현재 변화와 실제 참여자를 기준으로 관계장 재구성`
→ `현재와 연결된 완결 경험만 재활성화`
→ `현재 참여상태와 역사적 참여 분리`
→ `현재 행동 가능성 + 조건을 만족하는 과거 경험 행동의 재참여`
→ `관계·전제조건·책임 해결에 의한 가능성 조합 확장`
→ `명시적 불변 제약 검사`
→ `미해결 책임의 집합 포함관계로 비지배 후보 구성`
→ `현재 흐름에 직접 참여하는 후보 확인`
→ `여전히 비동등 후보가 여럿이면 계산 재현성용 결정적 타이브레이커`
→ `한 선택만 실제화`
→ `실제 결과가 세계의 사실·관계·참여·행동가능성을 변경`
→ `실제 선택+결과만 완결 경험으로 저장`
→ `이후 현재에서 관련 경험이 다시 의미를 얻으면 재참여`
→ `과거 경험과 새 완결 경험 사이에 나선 계보 기록`

## 타이브레이커 경계

비지배 후보가 여러 개 남아도 OASIS는 이를 하나의 총점으로 환원하지 않는다. 다만 계산 시스템은 한 시점 한 현실화를 수행해야 하므로 결정적 구조키로 하나를 선택할 수 있다.

이 타이브레이커는 OASIS의 철학적 선호가 아니다. `tieBreakUsed=true`인 실행은 선택 우월성의 증거로 사용할 수 없다.

영문 설명:
- `tie-break`는 여러 후보가 판단구조상 끝까지 비동등하게 남았을 때 실행 재현성을 위해 하나를 선택하는 계산 장치다.

## 외부 세계와의 인터페이스 경계

코어는 현실을 스스로 만들어 넣지 않는다. 외부 환경 어댑터가 다음을 제공한다.

1. 현재 현실에서 실제로 관찰된 사실과 관계
2. 현재 현실에서 실제로 실행 가능한 원자 행동 기회
3. 실제화된 선택 뒤에 현실에서 발생한 결과

영문 설명:
- `Affordance`는 현재 환경이 실제로 허용하는 행동 기회 또는 실행 가능성을 뜻한다.
- `Adapter`는 역사자료, 게임세계, 물리환경 등 서로 다른 현실 표현을 OASIS 코어의 공통 입력형식으로 연결하는 변환 계층이다.

이 인터페이스는 실험별로 달라질 수 있지만 OASIS 코어의 내부 선택원리를 바꾸어서는 안 된다.

## 기본조건 최소개입

코어 자체는 진행 불능 시 기본조건을 자동 주입하지 않는다.

행동 가능성이 없으면 `continuationRequired=true`를 반환한다. 실험 전체가 이 상태 때문에 지속 불가능할 때에만 외부 하네스가 최소 공통 조건을 추가하고, 해당 입력을 `intervention` 사건으로 명시적으로 기록한다.

## 실험 전 구현 승인 조건

새 검증은 다음을 모두 만족해야 실행할 수 있다.

1. 실험 코드가 `src/oasis-integrated-core.mjs`를 import한다.
2. OASIS 선행 4축 감사의 구현축을 통과한다.
3. `.github/workflows/oasis-integrated-core.yml`의 기반 감사와 확장 알고리즘 감사가 모두 통과한다.
4. 실험 하네스가 새로운 고정 임계값, 점수, 위험값, 성공값을 OASIS 내부에 삽입하지 않는다.
5. 실험별 세계 어댑터가 제공하는 정보와 개입을 전부 기록한다.

## 현재 의미

이 구현본은 OASIS 이론의 진실성을 증명하는 결과가 아니다. 현재까지 합의된 OASIS 개념을 실험 가능한 코드로 최대한 보존한 **논문검증 기준 구현본**이다.

향후 반증 실험에서 알고리즘 자체의 왜곡이나 누락이 발견되면 이 파일과 코드 버전을 함께 갱신하고, 기존 버전에서 얻은 결과와 새 버전의 결과를 구분한다.
