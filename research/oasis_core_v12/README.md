# OASIS G3 보완 구현 v1.2 / Supplementary implementation

상태: 보완 설계의 실행 가능한 경계·기록·연결 구현. Full-OASIS 완성본 또는 CARLA 운전 정책이 아니다.

기준 저장소: ChoJuneSeop/oasis-mvp1
기준 브랜치: implementation/oasis-core-v1.1-g32-current
기준 커밋: 2a12f27f90993442d309d3291728334b8bb02171
변경 분류: 보완 업데이트. 기존 v1.1 Core·Harness·G3.2 sidecar와 해시 고정 파일은 보존했다.

## 구현 범위 / Implemented scope

- B1: CurrentFrame(현재 관측 묶음)은 실제 시간 tau와 의사결정 번호 epoch를 구분한다. 현재 증거는 승인된 관측 필드와 일치해야 한다. 과거 경험은 완결시각 및 수신시각 모두 현재 이전인 경우에만 의미 연산에 제공한다.
- B2: CompletedProcess(완결 관계과정)는 실제 관측·관계 범위·경계 근거를 요구한다. 상태 변화, 행위 실행 또는 모든 후속 결과의 종료를 필수로 두지 않는다. 기존 실제 행위 HistoryEntry는 HistoryAdmissionBridgeV12로 연결한다.
- B3: 참여 경로와 재구성 관측은 분리한다. 역할 문자열을 고정 열거형으로 제한하지 않는다. c/v/s 미측정은 None(미측정)으로 남기며 측정 방법·비교 근거·대응관계를 기록한다.
- B4: 원본 경험은 덮어쓰지 않는다. 동일 배치 재입력은 멱등적(반복해도 추가 효과 없음)이고, 충돌 배치는 전체 거부한다. 겹치는 경험의 공통 발생 기록은 분포의 경로 수에서 중복 계산하지 않는다.
- B5: 후보는 등록된 현재 증거를 참조해야 한다. 새 재구성 후보는 출처를 가진 관측 기록이 필요하다. 기존 후보 생성기와 재구성 연산자 분리는 유지한다.
- B6: 선택, 실행 시도, 적용 확인, 이후 관측을 구분한다. SQLite(로컬 데이터베이스)에 외부 호출 전 실행 예약을 남겨 응답 유실·재시작 후 자동 중복 실행을 막는다. 적용 확인은 결과 성공 판정이 아니다.
- B7: U/I/V/T 개별 변수와 주입형 책임 연산자를 유지한다. 추가 변수는 이름별 현재 증거 참조를 요구한다. 자원 요구량·가용량·배정량·미검증 범위를 구분하고 실행 전 시간제약과 권한을 확인한다.
- B8: ProcessArchive(과정 기록 보관소)는 지연 관측과 정정 근거를 추가 기록한다. 과거 시점 조회에는 당시 미수신 정보를 반환하지 않는다. 지연 관측 연결을 인과효과의 입증으로 표시하지 않는다.

## 실행 / Run

Python 3.11 이상, 표준 라이브러리만 사용한다. 저장소 루트에서 실행한다.

```bash
python -m unittest research.oasis_core_v12.test_supplement -v
python -m research.oasis_core_v12.synthetic_integrated_flow
python -m research.oasis_core_v12.verify_manifest
```

synthetic_integrated_flow(합성 연결 예제)는 첫 적용 확인 → 완결경험 편입 → 다음 현재에서 과거 관계 재참여 → 지연 결과 추가의 연결을 실행한다. 기존 v1.1 합성 도메인 연산자를 재사용한다. 내부 숫자는 코드 연결용 자료이며 G3 수학식 또는 실제 운전 기준이 아니다.

## 기존 코드와 연결 / Integration

CurrentRelationalCoreV12에는 v1.1과 같은 relation_builder, candidate_provider, relation_operator, reconstruction_operator, responsibility_operator, choice_operator, actuation_operator를 주입한다. 새 Core 구현은 v1.1의 연산 순서를 복제하여 확장했다. 타입·기존 도메인 연산자·G3.2 기록 형식을 재사용하고 원본 파일은 변경하지 않았다.

현재 관측은 open_current_epoch(CurrentFrame)로 열어야 한다. 완료시각과 단순 epoch 번호를 자동으로 같은 척도로 취급하지 않는다. history 인자는 HistoricalEnvelope(완결·수신·발생 출처를 포함한 기록) 목록이다. 외부에 반환되는 과거 기록과 현재 분포는 내부 기록을 수정하지 못하도록 복사한다.

G3.2 부수 기록기의 개별·공동 관계 개입 API는 유지된다. 계측에는 동일한 관측을 고정한 별도 복제 환경과 순수한 도메인 연산자가 필요하다. 새 실시간 실행 경로는 기존 Harness의 '판단 중 현실 불변' 가정을 옮겨 사용하지 않으며, 실제 현실에서 진단 개입을 자동 실행하지 않는다. 관측이 바뀌면 StaleDecision(판단 전제 변경)을 반환하고 호출자가 현재 관측에서 다시 판단한다.

LiveActuationPort(실행 연결부)는 capture로 승인된 관측만 반환하고 apply_if_current에서 현재 revision(관측 전제 버전) 검사 및 idempotency_key(중복 방지 식별자)를 원자적으로 처리해야 한다. Core에는 이 연결부나 원본 world/map/actor를 전달하지 않는다. run_id·subject_id는 재시작 후에도 동일한 실행·주체에 동일하게 유지해야 한다.

SQLite는 실제 외부 환경과 하나의 트랜잭션이 아니다. 실행 예약 후 중단되면 미확인 상태가 남고 자동 재시도를 금지한다. 외부 적용의 정확히 한 번 성공을 이 코드만으로 보장하지 않는다. 실제 연결부의 원자적 검사·중복 방지 구현이 필요하다. 실시간 드라이버는 StaleDecision을 처리하면서 현재 흐름을 계속 받아야 한다. 무한 재시도나 고정 안전행동을 내부에서 만들어 넣지 않았다.

## 내부 필요성 검토 / Internal necessity review

코드 작성 전에 OASIS_RESEARCH_PROTOCOL.md, v1.1 Core·HistoryAdmissionBridge·CanonicalHarness, G3.2 INTEGRATION_CONTRACT 및 기존 회귀 검사를 확인했다. 외부 이론 삽입이나 신규 효능 실험의 필요성은 없었다. 기존 코드에 직접 확인된 결손은 다음과 같다.

1. add_history는 같은 출처 식별자의 기록을 덮어쓸 수 있었다.
2. Core 내부는 명시적인 수신시각 없이 전체 과거 기록을 읽었다. sidecar 검사 이전의 의미 연산에서 이를 방지할 필요가 있었다.
3. 참여 경로의 현재 관계 식별자가 실제 관계 집합에 속하는지 검사가 없었다.
4. 재구성 후보의 현재 증거는 비어 있지 않은 문자열만으로 통과할 수 있었다.
5. 기존 Harness는 동기식 현실 불변 조건을 전제했고, 응답 유실 후 재시작을 위한 지속적인 실행 예약이 없었다.
6. 재구성 관측의 미측정과 측정된 0을 구분하는 형식, 지연 결과의 과거 시점 조회 경로가 필요했다.

이번 검사는 위 결손에 대한 회귀·부정 입력·전체 연결 검사다. OASIS 이론의 독립 분해 실험이나 새 인과효과 실험이 아니다. 과학 실험은 별도로 필요성 킬서치와 사전 고정을 거쳐야 한다.

## 남은 정의와 실증 / Remaining definitions and validation

- Trace incidence(출처 경로 수 기반 분포)는 기존 측정용 구현을 확장한 기준 연산이다. 후보 간 원래의 경로 수 비교에는 아직 과학적 정당화가 필요하다. 보정된 현실화 확률이나 안전도라고 주장하지 않는다.
- 등록된 현재 증거가 후보의 실행가능성을 의미상 충분히 지지하는지는 도메인 연산자가 검증해야 한다. 식별자 무결성 검사는 그 의미 검증을 대체하지 않는다.
- 현재 후보 집합은 실제 구성된 집합이다. 전체 가능성 탐색 완료를 주장하지 않는다. 빈 집합은 실행 불가 오류이며 시스템 종결이 아니다.
- 경험 완결·관계 의미 추출·현재 역할 도출·c/v/s 수치 계산·책임변수 추가/제거·검증 자원 배분 정책은 실제 도메인 연산자의 계산 정의가 필요하다. 이번 코드는 이 정의를 임의 가중치나 임계값으로 대신하지 않았다.
- ProcessArchive의 지연 관측은 자동으로 의미 연산에 편입되지 않는다. 새로운 관측에서 도출한 관계를 출처가 있는 새 완결 기록으로 편입해야 한다. 원래 경험과 당시 판단은 보존된다.
- 승인된 관측, 완결 증거, 실제 적용 영수증의 사실성은 신뢰된 게이트웨이의 책임이다. 임의 Python 연산자에 대한 보안 격리나 전역 부작용 방지는 구현하지 않았다.
- Core는 단일 쓰기 실행을 전제한다. 실행 예약은 DB 유일키로 중복을 막으며, 다중 프로세스 공유 Core 상태 조정은 별도 구현 대상이다.
- 실제 CARLA 실행은 기존 CARLA_DOMAIN_POLICY_CONTRACT.md의 소스 고정·관측 경계·정책 검사 완료 전까지 차단 상태다.
