# GH-2 v1.1 Restart Plan

GH-2 v1.0 pilot provenance is retained as diagnostic-only evidence. It is not admissible for confirmatory inference because the v1.0 scenario generator discarded the recorded seed, the confirmatory block-count method was not mathematically frozen before pilot, and pre-execution tests inspected the same evaluator-resolution contrast later intended for experiment interpretation.

GH-2 v1.1 restarts before experiment execution under these rules:

1. Preserve GH-1, GH-1L, Core, and GH-2 v1.0 history unchanged.
2. Keep the four responsibility arms: R1 CURRENT_BOUND, R2 RECORD_ONLY, R3 PERMUTED, R4 STALE.
3. Pilot is structural only: four single-axis matched critical/relief pairs (8 frames). It cannot determine sample size or support a scientific claim.
4. Confirmatory size is frozen a priori as a finite exhaustive matrix, not pilot-derived: 11 multi-axis combinations x 2 contexts x 3 frozen observation families = 66 frames per arm.
5. Pilot and confirmatory scenario classes are disjoint.
6. Evaluator truth never enters worker/runtime payloads. Preflight/admission tests must not compute confirmatory resolution, R1>R2, or any hypothesis-support statistic.
7. R4 stale responsibility is pair-local: the critical frame may seed stale state only for the matched relief frame; stale state is reset at every new matched pair.
8. U/I/V/T responsibility remains candidate-specific, set-valued, non-scalar, current-contextual, and downstream of the actual Core possibility set.
9. Historical participation, outcome-feedback reuse, newly committed CE reuse, and revalidation learning remain disabled for all arms.
10. Pilot/confirmatory execution remains locked until v1.1 pre-execution gates and frozen-lineage regressions pass on an exact commit.

This document is a pre-execution amendment. No GH-2 v1.1 pilot or confirmatory result existed when these rules were written.
