# 선택·책임 통합 과정 v0.1 / Choice–Responsibility Integration

**이 작업은 기존 G3 보완 코딩과 구분되는 별도의 통합 과정이다.**

2026-09-12 「AI 종말론 재부상」 논의에서 병행하기로 한 선택·책임 연결을, 업로드된 G3 보완 구현 v1.2 위에 추가했다. 사용자의 “지금 통합하고 별도의 과정임을 밝히고 깃허브에 업로드하라” 요청에 따른 작업이다.

- 과정 식별자: `choice-responsibility-integration-v0.1`
- 기준 커밋: `91f33ece689808bf85aa3220e3d42cd55b468980`
- 분류: 보완 통합 구현. G3 본선의 완성·동결 선언이나 G4 진입이 아니다.
- 기존 Core v1.1·G3.2 sidecar·G3 보완 v1.2 소스는 수정하지 않았다.
- 이번 결과는 실행 가능한 연결과 코드 검사다. AI 안전성·종말 위험 감소·Full-OASIS 효능 실증이 아니다.

## 연결한 흐름 / Integrated flow

현재 현실과 현재 관계 → 과거 관계의 재참여 → 참여·재구성·가능성 분포·U/I/V/T → 현재 검증 요구와 충돌 추적 → 실제 검증 수행과 미검증 책임 → 현재 제약에 따른 단일 선택 → 실행 확인 → 완결경험 편입 → 남은 책임을 가진 이후 재참여 → 지연 관측.

이 순서는 자료 전달 관계를 나타낸다. 모든 현실 관계가 단순 선형 과정이라는 주장은 아니다.

| 이전 결손 | 이번 구현 |
| --- | --- |
| 재구성 관측을 선택에 직접 전달하지 않음 | 전체 EpochEvaluation(현재 평가)의 재구성·참여·분포·책임벡터를 ChoiceContext(선택 맥락)에 포함 |
| 미검증 범위를 기록만 함 | VerificationReport(검증 수행 기록)의 Omega(오메가, 미검증 책임)를 선택에 직접 전달하고 현재 실행조건과 연결 |
| 요구량과 실제 수행량의 연결 부족 | 현재 VerificationRequest(검증 요구) 목록에서 요구량을 산출하고 실제 수행량·남은 요구를 별도 보존 |
| 충돌 관계 추적 부재 | ConflictTrace(충돌 관계 기록)에 현재 관계, 과거 출처, 현재 근거, 자유로운 반응 기술자를 연결 |
| 완결 이후 책임 연결 부족 | 실제 적용 기록과 완결경험을 대조하고 미검증 책임 및 원래 선택 맥락을 보존 |
| 4분법을 넘는 경로 확인 부족 | 선택·적용·완결·현재 재참여·지연 관측을 출처로 연결한 시점별 trajectory(전체 진행 경로) 보고 |

## 실제 선택 규칙 / Executable selection rule

`IntegratedChoiceCore`는 기존 `CurrentRelationalCoreV12`를 확장한다. 기존 현재 관계·후보·재구성·책임 연산자는 재사용한다. 이전의 선택 호출로 돌아가는 우회 경로는 허용하지 않는다.

1. `assessment_operator.assess`에 현재 평가 전체와 현재 다시 참여한 경험의 미해결 책임을 전달한다. 여기에서 해당 도메인의 현재 검증 요구, 실행조건, 충돌 관계를 도출한다.
2. 요청별 현재 증거와 후보·관계·과거 출처의 유효성을 검사한다. 요청 작업량 합계는 현재 자원 계획의 요구량과 일치해야 한다.
3. `verifier.verify`에 요청, 현재 입력, 남은 작업 한도를 전달한다. 실제 수행량과 질문별 충족·불충족·미확인을 기록한다. 예산 부족으로 수행하지 못한 요청도 원래 질문·현재 근거와 함께 Omega로 남긴다.
4. `CurrentContextChoice`는 **현재 근거에서 명시된 실행조건**을 적용한다. 그 조건이 요구하는 검증이 충족되지 않은 후보는 이번 선택에서 제외한다. 미검증이 있다는 이유만으로 모든 후보를 자동 금지하지 않는다. 비필수 미검증 범위도 선택 맥락과 기록에 유지한다.
5. 남은 후보와 전체 맥락을 `preference_operator.choose`에 직접 전달한다. 이 연산자는 참여·재구성·U/I/V/T·충돌·검증 수행·Omega·현재 제약을 읽을 수 있다. 반환값이 현재 허용 후보에 속하는지 다시 확인한다.
6. 현재 허용 후보가 없으면 선택 맥락과 미해결 책임을 기록하고 행동을 적용하지 않는다. 이를 인연필드 종결, 의도적 대기 선택 또는 세계의 실패로 판정하지 않는다.

책임벡터를 단일 위험 점수로 합치지 않는다. 고정 참여 역할, 고정 재구성 등급, 보편 위험 임계값을 추가하지 않았다. 구체적인 실행조건은 매 현재 시점에 근거와 함께 공급되며 이후에 바뀔 수 있다. 선택 조건에 따른 후보의 허용 여부는 실행 전제 검사이며 결과 전체에 대한 분류가 아니다.

## 4분법 처리 / Four-way descriptions

4분법은 최종 결과 판정기로 구현하지 않았다. 충돌에 대한 반응 설명은 길이 제한이나 고정 열거형이 없는 `response_descriptors`다. 다섯 번째 설명이나 새로운 표현도 허용한다. 이 설명 라벨 자체가 후보를 선택하거나 안전·실패를 결정하지 않는다.

`TrajectoryJournal.report`는 관측된 시간까지의 선택·실행·경험·재참여·지연 관측을 반환한다. `global_outcome_classification`은 None(단일 결과분류 없음), `causal_effect_established`는 False(인과효과 입증 아님)로 명시한다. 유효한 장기 비교 기준을 정의하지 않은 채 성공·실패 총점을 만들지 않았다.

## 완결과 이후 흐름 / Closure with continuation

`ResponsibilityHistoryBridge`는 실제 적용 확인이 있어야 행위에 대한 완결경험을 편입한다. 선택된 후보·현실화 참조·선택시각·적용 확인시각을 원래 기록과 대조한다. 완료 순간 남은 책임을 없애지 않는다.

원래 선택 맥락은 실행 기록에 보존되고, 완결경험과의 연결도 기록된다. 미검증 요청과 추가 미검증 범위는 완결경험의 `unresolved`에도 보존된다. 그 경험이 이후 현재 관계에 다시 참여하면 `reentered_unresolved`로 현재 평가자에게 전달된다. 과거의 미검증 항목을 현재의 명령으로 자동 재실행하지 않고 현재 근거에서 다시 판단한다.

지연 관측은 수신시점의 추가 기록이며, 과거 시점 보고를 소급 변경하지 않는다. 관련 경험이 이후 판단에서 실제 기여한 경우에만 `reentered_from` 연결을 기록한다. 단순히 기억에 남아 있다는 이유로 참여 또는 인과효과를 선언하지 않는다.

## 실행 / Run

Python 3.11 이상, 표준 라이브러리만 사용. 저장소 루트에서:

```bash
python -m unittest research.choice_responsibility_v01.test_integration -v
python -m research.choice_responsibility_v01.example
python -m research.choice_responsibility_v01.verify_manifest
```

합성 예제는 기존 도메인 연산자를 재사용한다. 현재 검증에 작업 단위 1과 2를 배정한 경우를 사용하여, 미검증 실행조건 때문에 첫 선택이 `yield`(양보)이고 다음 현재에서 검증을 수행한 후 `proceed`(진행)가 선택되는 연결을 확인한다. 이 숫자·조건·선호는 **검사용 자료**이며 OASIS의 보편 선택 법칙이나 실제 운전 기준이 아니다.

## 내부 필요성 확인 / Internal necessity review

새 코드를 쓰기 전에 기존 G3 v1.2의 `realize`, `ResourcePlan`, 실행 기록, 경험 편입 코드를 대조했다. 재구성·Omega가 선택 호출의 직접 입력이 아니었고, 실행 기록의 책임을 완결경험 이후 현재 재참여로 잇는 경로가 없었다. 기존 59개 검사는 이 신규 연결을 검증하지 않았으므로 추가 검사가 필요했다.

이번 검사는 전체 코드 경로를 보존하는 입력 전달·현재 조건·실행·출처 연결 회귀 검사다. 새로운 OASIS 효능 실험을 실행한 것이 아니며 외부 이론을 삽입하지 않았다. 인과·안전성 실험은 별도 필요성 킬서치와 사전 고정 후에 수행해야 한다.

## 남은 경계 / Remaining boundaries

- 계산 가능한 통합 연결과 기준 실행조건 처리기를 구현했다. 도메인별 검증 요구 도출, 검증의 의미상 타당성, 선호 선택 법칙은 별도로 정당화·고정해야 한다. 어떤 주입형 연산자가 모든 입력을 유의미하게 사용하는지까지 인터페이스만으로 입증할 수는 없다.
- 검증기는 현재 관측 복사본만 받아야 한다. 임의 Python 콜백의 외부 접근이나 실행 시간을 강제로 격리하지 않는다. 실제 자원 계량은 검증기의 보고를 신뢰하며, 보고 초과는 거부하지만 이미 사용한 CPU 시간을 되돌리지 못한다.
- `work_limit`은 선언된 작업 단위다. 실행 직전 시간과 현재 관측을 다시 확인하지만 하드웨어 실시간 기한 보장은 아니다.
- 검증 중 새 현실을 직접 읽어 판단에 섞지 않는다. 실제 연결부의 관측 버전이 바뀌면 실행을 중단하고 현재 입력에서 새 판단을 구성해야 한다.
- 실행 예약·중복 방지 및 실제 연결부의 원자적 전제 검사 요구는 v1.2를 승계한다. 외부 적용의 정확히 한 번 성공 보장은 실제 연결부 구현이 필요하다.
- 실행 기록과 경험 보관소는 서로 다른 데이터베이스일 수 있다. 편입은 단일 쓰기·멱등적 재시도를 전제로 하며 분산 트랜잭션을 제공하지 않는다. 기록이 중간에 끊기면 완료 연결을 다시 확인해야 한다.
- 시점별 보고에는 확인된 시간값이 있는 사건만 포함된다. 통신 오류처럼 시각을 얻지 못한 사건은 원래 실행 기록에 남으며 과거 조회에 임의의 시각을 만들어 넣지 않는다.
- 전체 경로 기록은 장기 평가의 입력이다. 생명가치 제약의 도메인 구현·장기 인과 평가·독립 검증·실제 CARLA 실행은 이번 코드 통합으로 완료됐다고 간주하지 않는다.
