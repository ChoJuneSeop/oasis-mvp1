## 0. Kill-search: is another Ω experiment necessary?

### 0.1 What is already known outside OASIS
Hierarchical reinforcement learning, options, macro-actions, skills, and long-horizon planning already establish that temporally extended action sequences can be represented, learned, transferred, and composed. Therefore the following claims are NOT OASIS-specific and are killed as novelty targets:

- multi-step actions can improve long-horizon behavior;
- action abstraction can matter;
- macro-actions/options can alter trajectories;
- compositional planning exists.

### 0.2 Why unchanged Ω v1 is killed
The existing Ω v1 eligibility only requires that atomic and admissible composite possibilities coexist. Its controls distinguish atomic-only from a count-matched mixture, but do not distinguish:

1. online possibility construction from a frozen macro-action library;
2. dependency-grounded composition from generic long action sequences;
3. current-flow novelty from pre-enumerated temporal abstractions.

Therefore an unchanged Ω v1 run cannot answer the OASIS priority question “why OASIS?”. It is unnecessary and must not be used as the confirmatory Ω test.

### 0.3 Surviving necessity question
The Ω v2 experiment is necessary only to test this narrower question:

> When the current reality creates new token/entity/relation/bridge dependencies, does Ω's online construction of executable possibilities change later external reality beyond (a) atomic actions only, (b) a frozen pre-enumerated macro library, and (c) merely having equally many/equally deep long action sequences?

This is a causal-necessity test for Ω in the current OASIS flow, not a general superiority test.

## 3. Ω v2 baseline semantics

Ω receives currently instantiated primitive steps and may construct a composite only when the next step is enabled by at least one actual sequential dependency from the prior partial possibility:

- token dependency: prior step provides a required token/fact;
- entity dependency: prior step creates an entity required later;
- relation dependency: prior step provides/activates a required relation kind;
- explicit bridge dependency: prior step provides a required bridge key.

Entity co-membership alone is insufficient.

A composite possibility is not treated as better because it is composite. No score, probability, Ψ, responsibility, morality, reward, preference, or choice weight may be increased merely for being generated by Ω.

---

## 4. Frozen macro-library control

A new Ω v2 baseline kernel may record diagnostics without changing intact behavior.

For each actor, on the FIRST Ω call only, freeze a `macroLibrary` containing structural signatures of the composite possibilities available at that first current reality. The library is immutable thereafter.

A macro signature must contain only structural information required to identify the action/dependency skeleton, such as ordered capability/action identities and dependency-kind pattern. It must not contain:
- outcome success/failure;
- civilization labels;
- future information;
- reward/value/importance;
- confirmatory seed outcome statistics.

The library is seed-local but frozen before later reality unfolds for that actor. It is never updated from later experience.

The static-macro branch may instantiate a current composite only if its structural signature exists in this frozen first-current library and the candidate is currently physically admissible.

## 5. Confirmatory branches

### O0 — INTACT ONLINE Ω
Post-Gamma-v2 full OASIS baseline. Online dependency-grounded Ω remains intact.

### O1 — ATOMIC ONLY
After onset, preserve observation, Gamma, participation, primitive instantiation, history, W, choice policy, life constraint, responsibility, and world physics. Block only Ω candidates with sigma depth >= 2. Atomic possibilities remain identical to O0.

### O2 — FROZEN MACRO LIBRARY
After onset, preserve O0 atomics. Composite possibilities are limited to currently valid composites whose structural signature is already in that actor's immutable first-current macro library. No new macro signature may enter later.

This tests whether pre-enumerated temporal abstractions are sufficient.

### O3 — COUNT+DEPTH MATCHED INDEPENDENT-SEQUENCE SHAM
After onset, preserve O0 atomics. Replace dependency-grounded O0 composites with deterministic sham sequences such that, when available:
- returned composite count exactly matches O0 composite count;
- sigma-depth histogram exactly matches O0 composite depth histogram;
- each primitive step in a sham is independently startable from the same current observation;
- adjacent sham steps are NOT linked by token/entity/relation/explicit-bridge dependency from prior step to later step;
- the sequence passes physical dry-run validation;
- no historical, reward, civilization, future, or preference signal is used.

If exact count+depth matching is impossible, mark `SHAM_MATCH_NOT_AVAILABLE`; only O0–O3 interpretation for that seed/horizon is invalid. O0–O1 and O0–O2 remain evaluable.

This tests whether generic long-sequence availability/candidate expansion explains the effect.

## 6. Mandatory pre-run audits (fail closed)

### A. Baseline equivalence
Before intervention, Ω v2 intact output must be behaviorally identical to the post-Gamma-v2 baseline for deterministic fixtures. Macro-library recording may add diagnostics only.

### B. Macro immutability
The first-current macro library is frozen once, independent of outcomes, and cannot update after later observations/realizations.

### C. Atomic-only exactness
O1 must return exactly the same atomic possibilities as O0 and no composite possibilities. Shared atomic fields must deep-equal.

### D. Static-macro restriction
O2 may return only O0 composites whose structural signatures are already in the frozen macro library. No later-created structural signature may enter O2.

### E. Sham validity and matching
For a hand-built fixture with sufficient pool, O3 must exactly match O0 composite count and depth histogram, while every sham step is independently current-startable and no adjacent dependency bridge exists. Dry-run must execute no real world action.

### F. No preference injection
For candidates shared across branches, Ψ, responsibility, life, and choice inputs must be identical. Only candidate existence/sequence structure may differ.

### G. No branch leakage / dry-run purity
Branch id is not visible to agent, observer, world, choice policy, or metrics. Eligibility/onset scanning executes no branch choice and no world action after the counterfactual comparison point.

Any failure blocks the confirmatory workflow.

## 11. Interpretation rules

### Ω causal support
O0 vs O1 must show reproducible downstream external divergence. This supports a causal role for composite possibility construction in this environment.

### Online-generative Ω support
In addition, O0 vs O2 must show reproducible external divergence at online-novel onsets. If O2 reproduces O0, a frozen macro library is sufficient here and online generation is not shown necessary.

### Specificity beyond generic long sequences
O3 must NOT reproduce the O0 pattern to the same extent. If O3 reproduces O0, generic long-sequence/candidate-expansion is a sufficient explanation.

### Bounded null
Valid O0 = O1 gives a bounded null for Ω composition in this environment.

### Static-macro sufficiency
Valid O0 = O2 despite online-novel gate means pre-enumerated macro structure is sufficient for observed external trajectory under this environment.

### Decomposition-induced failure
If O1 or O2 accidentally removes primitive abilities/current observation/Gamma/history or otherwise collapses the system beyond Ω candidate construction, classify implementation-invalid/decomposition-induced failure, not theory falsification.

## 12. Relation to the top-priority OASIS question

This experiment addresses only one part of:

> What becomes unobservable/unreachable if OASIS is removed?

A positive Ω-specific result would support the narrower answer:

> A moving reality can create executable combinations that were not represented in a frozen earlier possibility library; Ω preserves the ability to construct those current-dependent possibilities without assigning them privileged value.

It does NOT by itself prove that OASIS is globally superior or uniquely necessary across all domains.
